== Parasol-store-api OpenAPI 가져오기

. {product_name_rhdh}에 액세스하세요(https://backstage-backstage.{openshift_cluster_ingress_domain}[여기를 클릭하세요^, window="rhdh"]). 메시지가 표시되면 ``dev1/{common_password}``를 사용하여 로그인하세요.
. 왼쪽 탐색창에서 *Create* 메뉴를 클릭하고, *Import Existing API* 템플릿에서 *Choose* 버튼을 클릭합니다.
+
image:m4/import-api-template.png[width=30%]
. 소프트웨어 템플릿 마법사가 표시됩니다. +
+
[NOTE]
====
이 필드 중 상당수는 편의를 위해 기본값으로 미리 채워져 있습니다. 실제로는 개발자가 기존 앱/API를 가져오는 데 필요한 거의 모든 값을 제공해야 합니다.
====
. *Step 1: Information about your existing API*. 다음 값을 입력하고 **Next**을 클릭합니다.
+
[cols="1,1,2", options="header"]
|====
| *Field* | *Description* | *Value*
| GitLab hostname | Keep default value | \https://gitlab-gitlab.{openshift_cluster_ingress_domain}
| GitLab Organization of Existing API | Keep default value | `parasol`
| Repository name of Existing API | Keep default value | `parasol-store-api`
| API specification path | Enter full path of the API | \https://gitlab-gitlab.{openshift_cluster_ingress_domain}/parasol/parasol-store-api/-/blob/main/openapi.yaml
| Type Of API | Keep default value | `openapi` 
|====
+
image:m4/import-api-1.png[] 


. *Step 2: New Component details*. +
등록하는 새 컴포넌트트에 대한 정보를 제공하세요. 다음 값을 입력하고 *Review*를 클릭하세요.
+
[cols="1,2,2", options="header"]
|====
| *Field* | *Description* | *Value*
| Component GitLab Organization | Keep default value| `parasol`
| Component Repository name | Keep default value | `all-location-parasol` 
| Component Name of API | Keep default value | `parasol-store-api`
| System Name | System (auto-populated) | `system:default/parasol-system`
| Owner | Choose from dropdown | `user:default/dev1`
| A Short Description Of This Component |Enter a suitable description | `Open API specification for the parasol-store application`
| Lifecycle | Enter value. Can be any lifecycle value, but take great care to establish a proper taxonomy for these. (Well-known values `experimental`, `production` and `deprecated`) | `production` 
|====
+
image:m4/import-api-2.png[]

. *Step 3: Review & Create.*  +
필드를 검토하고 *Create* 버튼을 클릭하세요.
+
image:m4/import-api-3.png[]

. *Run of import-api-catalog*: +
Component Merge Request URL이 제공됩니다.

+
image:m4/import-api-4.png[]

.링크를 클릭하여 병합 요청을 열고 *Merge* 버튼을 클릭하여 병합을 완료합니다. 
+
image:m4/api-template-merge-all-location.png[width=70%]

. https://gitlab-gitlab.{openshift_cluster_ingress_domain}/parasol/all-location-parasol[all-location-parasol repo, window="gitlab"]로 이동하면 ``catalog-info.yaml``과 ``TechDocs``에 대한 docs 폴더가 있는 ``parasol-store-api``라는 새 폴더가 생성된 것을 볼 수 있습니다. 
+
image:m4/parasol-store-api-gitlab.png[width=70%] 

=== API 섹션에서 `parasol-store-api` 컴포넌트 확인

. 방금 가져온 **Parasol Store API**가 곧 **API** 섹션에 자동으로 나타납니다. 이는 이전 단계에서 활성화한 자동 검색 기능 때문입니다. 
+
image:m4/view-api.png[]

** ``parasol-store-api``를 클릭하고 컴포넌트를 살펴봅니다. *Docs* 탭은 추가된 스켈레톤 techdocs를 표시합니다. 
** *Definition* 탭은 OpenAPI 사양을 잘 정리하여 보여줍니다.이는 API를 가져오는 동안 API 유형으로 ``openapi``를 선택했기 때문입니다. 
+

image:m4/view-api-definition.png[]

=== 카탈로그 섹션에서 `parasol-store` 컴포넌트 살펴보기

. 몇 분 안에 방금 가져온 `parasol-store` 컴포넌트트가 {product_name_rhdh}의 카탈로그 섹션에 자동으로 나타납니다. 
+
image:m4/view-parasol-store-component.png[]

. `parasol-store` 링크를 클릭하여 컴포넌트를 살벼벼봅니다. 각 탭을 단계별로 살펴보면 {product_name_rhdh}가 핵심 개발 요구사항에 대한 단일 창을 제공하는 방식을 확인할 수 있습니다. 

. **opology Tab**은 OpenShift 상의 Deployments를 보여줍니다 
+
image:m4/parasol-store-topo.png[]

. **CI Tab**은 모든 파이프라인 실행을 표시합니다. 아직 파이프라인 실행이 없으므로 현재는 비어 있습니다. 
. **CD Tab** 은 ArgoCD 플러그인을 사용하여 배포된 구성요소/시스템을 표시합니다.
+
image:m4/parasol-store-argo.png[]

. **Api Tab**은 사용된 API, 즉 ``parasol-store-api``를 보여줍니다. 종속성 탭도 살펴보시길 바랍니다.
. **Docs Tab**에는 템플릿에서 만든 스켈레톤 TechDocs가 포함되어 있습니다. ``연필 아이콘``을 클릭하여 문서를 편집할 수 있습니다.
