== 가져오기(Import) 소프트웨어 템플릿 등록

=== 소프트웨어 템플릿 개요

You learnt how to create a Software Template in module 3. In this section we will walk through a Template that has been pre-built for you. 

Click https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/import-existing-api-template/-/blob/main/template.yaml[here^, window="gitlab"] to view the `import-existing-api` Software Template you'll be using.

This template does the following:

. Gather details of the API (GitLab org name, repo name)
. Gather details of the new Software Component to be created (target location of the component, the catalog info, API Path etc)
. Creates a Merge Request to create the new catalog-info and TechDocs file of the component

당신은 3번째 모듈에서 소프트웨어 템플릿을 만드는 방법을 배웠습니다. 이번 섹션에서는 사전에 미리 만들어진 템플릿을 살펴보겠습니다.

https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/import-existing-api-template/-/blob/main/template.yaml[여기^, window="gitlab"]를 클릭해서 여러분이 사용할 `import-existing-api` 소프트웨어 템플릿을 확인하세요.

이 템플릿은 다음을 수행합니다.

. API의 세부사항을 수집합니다. (GitLab 조직 이름, 레포지토리 이름)
. 새로 생성될 소프트웨어 컴포넌트의 세부사항을 수집합니다. (컴포넌트의 대상 위치, 카탈로그 정보, API 경로 등)
. 새 카탈로그 정보 및 TechDocs 파일을 생성하기 위해 병합 요청을 생성합니다.

=== Import API 소프트웨어 템플릿 등록

. {product_name_rhdh}에 액세스하세요(https://backstage-backstage.{openshift_cluster_ingress_domain}[여기를 클릭하세요^, window="rhdh"]). 메시지가 표시되면 ``pe1/{common_password}``를 사용하여 로그인하세요.

. 다음 URL을 *Select URL* 필드에 붙여넣고 *Analyze* 버튼을 클릭합니다. 이 URL은 Software Template의 https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/import-existing-api-template/-/blob/main/template.yaml[template.yaml, window="gitlab"] 파일을 가리킵니다.
+

image::m4/nav-register-wizard.png[]

=== Import App 소프트웨어 템플릿 등록록

== GitLab 엔티티 자동 검색 설정

새 템플릿은 새로 생성된 엔티티를 탐지하기 위해 다음과 같은 동적 플러그인 세트를 필요로 합니다:

* **roadiehq-scaffolder-backend-module-utils-dynamic**: 파일 시스템을 조작하는 데 사용됩니다. 이 경우에는 새로 생성된 `catalog-info.yaml` 파일을 GitLab에 커밋하는 데 사용됩니다.
* **backstage-plugin-catalog-backend-module-gitlab-dynamic**: `catalog-info.yaml` 파일의 자동 검색을 가능하게 합니다.
* **immobiliarelabs-backstage-plugin**: GitLab과 상호작용하여 병합 요청, 이슈, 파이프라인 실행 등을 생성하는 데 사용됩니다.

=== 플러그인 활성화

. 또한 GitLab에서 병합을 요청하고 이슈를 보기 위한 몇 가지 커뮤니티 플러그인을 활성화할 것입니다.
. https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/developer-hub-config/-/edit/main/values.yaml[GitLab의 rhdh/developer-hub-config 저장소^, window="gitlab"]로 이동합니다. 로그인하라는 메시지가 표시되면 ``pe1/{common_password}``를 사용하여 로그인하세요.
. 이미 ``values.yaml`` 파일의 편집 모드에 있을 것입니다.
. `--- DYNAMIC_PLUGINS_IMPORT_COMPONENTS ---` 주석을 찾습니다.
. 아래 스크린샷에 표시된 YAML 섹션을 강조 표시하고 해당 줄의 주석 처리를 제거합니다. ``CMD + /`` 또는 ``CTRL + /``를 사용하여 주석을 해제할 수 있습니다.
+
image::m4/uncomment-dynamic-plugin.png[width=60%]
. 아직 변경사항을 커밋하지 마세요. 자동 검색도 활성화해야 합니다.

. 같은 `values.yaml` 파일에서 주석 ``--- AUTO_DISCOVERY_IMPORT_COMPONENTS ---``를 찾습니다 
. 아래 스크린샷에 표시된 대로 YAML을 강조 표시하고 해당 줄의 주석 처리를 제거합니다. 
+
image::m4/uncomment-auto-discovery.png[width=60%]
+
NOTE: 이 YAML 스니펫은 이름이 __all-location__(projectPattern)으로 시작하는 리포지토리에서 __all-location.yaml__(entityFilename)이라는 이름의 모든 파일에 대해 자동 검색을 활성화합니다.

== Parasol의 시스템과 도메인 온보딩

In a previous chapter you learnt how https://backstage.io/docs/features/software-catalog/system-model#system[System,window="content"] and https://backstage.io/docs/features/software-catalog/system-model/#domain[Domain,window="content"] Entities help organize and provide a hierarchy of Components in {product_name_rhdh}. In this section you will setup Parasol's System and Domain.

이전 챕터에서 https://backstage.io/docs/features/software-catalog/system-model#system[System,window="content"] 및 https://backstage.io/docs/features/software-catalog/system-model/#domain[Domain,window="content"] 엔터티가 {product_name_rhdh}의 컴포넌트를 조직하고 계층을 제공하는 방법에 대해 배웠습니다. 이 섹션에서는 Parasol의 시스템 및 도메인을 설정합니다. 

. {product_name_rhdh}에서 Create 메뉴로 이동합니다. *Register Existing Component* 버튼을 선택합니다. 
. 아래 URL을 붙여넣고 **Analyze**를 클릭합니다.
+
[source,bash,role=execute,subs="attributes"]
----
https://gitlab-gitlab.{openshift_cluster_ingress_domain}/rhdh/rhdh-entities/-/blob/main/locations.yaml
----
. Review 섹션에서 **Import**를 클릭합니다.
. 시스템과 도메인이 설정되었습니다.  

[NOTE]
====
시스템은 관련 엔터티를 위한 기본적인 캡슐화 수준입니다. 도메인은 용어, 도메인 모델, 비즈니스 목적 등을 공유하는 시스템들의 집합을 그룹화하는 데 유용합니다.
====
