== 개발자 활동: 템플릿에서 새 컴포넌트 만들기

IMPORTANT: 이전 단계에서 안내한 대로 ``dev1/{common_password}``를 사용하여 개발자로 로그인했는지 확인하세요.

include::../style.adoc[]

플랫폼 엔지니어가 만든 *Quarkus Service* 템플릿을 사용하여 새로운 소프트웨어 컴포넌트와 지원 인프라를 만듭니다.

. 측면 메뉴에서 *Create* 항목을 선택하세요.
+
image:m3/rhdh-create.png[The {product_name_rhdh} Create UI]
. **Quarkus Service**에서 *Choose* 버튼을 클릭합니다. *Software Templates* 화면이 표시됩니다.
. 1단계에서는 애플리케이션 매개변수 집합을 입력하라는 메시지가 표시됩니다. 다행히도 템플릿에서 기본값이 제공되므로 **Next**를 클릭하기만 하면 됩니다. 
. 2단계에서는 *Provide Image Registry Information* 메시지가 표시되면 
  * *Quay* 이미지 레지스트리를 선택합니다. 
  * Quay 비밀번호 ``{common_password}``를 입력합니다.
  * **Next**를 클릭합니다.
+
NOTE: username은 현재 세션을 사용하여 템플릿에 의해 자동으로 결정됩니다.
+
image:m3/quarkus-service-step2.png[] 
. 3단계에서는 기본 **Repository Location**을 선택하고 **Review**를 클릭합니다.
+
image:m3/quarkus-service-step3.png[] 
. 매개변수가 적절한지 확인하고 *Create* 버튼을 클릭합니다. 
+
image:m3/rhdh-template-review.png[Reviewing template parameters in {product_name_rhdh}]

* 잠시 후 프로세스가 완료되면 일련의 녹색 체크 표시가 있는 화면이 나타날 것입니다.
+
image:m3/rhdh-template-success.png[A successful template run in {product_name_rhdh}]

* *Open Component in catalog* 링크를 클릭하여 새 컴포넌트를 봅니다. GitLab 저장소(*View Source* 링크)로 연결되는 링크가 표시되고, 컴포넌트를 직접 생성했기 때문에 소유자로 본인인이 나열되어 있음을 알 수 있습니다.
+
image:m3/rhdh-new-component.png[A successful template run in {product_name_rhdh}]

* *CI* 탭을 선택하여 OpenShift Pipelines(Tekton) 빌드의 상태를 확인합니다. 파이프라인이 나타나려면 1~2분 정도 걸릴 수 있습니다.
+
image:m3/rhdh-new-component-ci.png[CI status for the Quarkus Service]

* 빌드가 완료될 때까지 기다렸다가 https://quay.{openshift_cluster_ingress_domain}/user/dev1/[Quay의 dev1 조직^, window="quay"]을 방문하세요. 새로운 _my-quarkus-app_ 저장소에 새로 푸시된 _latest_ 이미지 태그를 볼 수 있습니다.
+
image:m3/quay-image-tag.png[Quay Latest Image Tag]

다음 섹션에서는 OpenShift GitOps(Argo CD)를 예시로 사용하여 컴포넌트에서 다양한 플러그인 통합을 활성화하고 비활성화하는 방법을 알아보겠습니다.
